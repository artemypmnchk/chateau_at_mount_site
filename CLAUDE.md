# Chateau At Mount — сайт

Next.js сайт винодельни. Задача сайта — продавать вино. Дев-сервер: `npm run dev`
(превью `chateau`, порт 3005). Источник правды по стилю — **`DESIGN.md`**: шрифты,
палитра «вино и известняк», железные правила, механика блоков. Любое визуальное
изменение обязано ему соответствовать.

## Workflow — спека до кода

Перед любым дизайн-блоком или заметным UI-изменением: сперва короткая спека
(research → лейаут → движение → цвета), СТОП на «ок» владельца, только потом код.
Не пропускать этот шаг, даже когда правка кажется мелкой — почти каждый провал
случался из-за прыжка сразу в (часто неверный) код. Для этого есть скилл `/spec` —
использовать его на редизайнах и новых блоках.

## Scope Discipline — трогать только то, что просили

- **Хиро не трогать** без явного разрешения владельца. Он — чистое фото без
  надписей и заметных затемнений; менял его не по просьбе — заворачивали.
- Менять ровно тот блок, что назвали. Не путать соседние (медали ≠ лента вин).
  Если неясно, какой элемент имеется в виду — спросить, а не гадать.
- Минимальный точечный диф. После правки перечитать соседние компоненты
  (reveal, ряд линеек LineRow, скрим, бургер) — свои же коммиты часто дают регрессии.
- Показывать диф, ограниченный одним блоком, до коммита.

## Design Preferences — сдержанно, не «ИИшно»

Аудитория заворачивает генерик и продающий пафос. Цель — редакторская, тихая,
премиальная типографика с авторским характером. Не выдавать: лавр+КАПС в наградах,
чипы/бейджи/«пилюли», цвет поверх фото, винную заливку на тёмном, шаблонные
«люксовые» приёмы, продающую копирайт-риторику. Тон текстов — сверять с владельцем
до финала, а не финалить молча. Детали и токены — в `DESIGN.md`.

## Verify — проверять в браузере, не перекладывать на владельца

После previewable-правки поднять `chateau`, проверить консоль/логи/сеть, `read_page`
на структуру, прогнать десктоп и mobile (390px), для анимаций — DOM-ассерты (не
только скрин: rAF-троттлинг врёт). Показать пруф скрином до/после. Не отдавать
работу словами «проверь сам».

## Working Style — решительно и коротко

- Меньше шагов, больше дела: не блуждать по exploratory-правкам.
- Направление неясно — не угадывать сериями попыток. Дать 2–3 конкретных варианта
  с однострочным трейд-оффом и попросить выбрать (AskUserQuestion).
- Заявки формы уходят в Telegram через `/api/lead` (не mailto). Владельцу нужен
  бот и env на Vercel — напомнить при деплое.
